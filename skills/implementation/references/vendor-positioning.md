# Vendor positioning

Control named vendor recommendations in discovery, fit assessment, and rejection recovery.

## Default rule

Do not introduce, rank, endorse, or recommend a named Lago competitor or alternative vendor. Recommend the required capability category, the ownership boundary, and the criteria the user should evaluate instead.

A vendor name may appear only when:

- the user already named that vendor and it is necessary to describe the user's current architecture;
- current official Lago documentation identifies it as an integration and it is necessary to explain verified interoperability; or
- Lago maintainers explicitly approved it in the registry below for the exact stated scope.

The first two cases permit factual architecture discussion, not an endorsement, ranking, procurement recommendation, or claim that the vendor is best. Verify time-sensitive integration claims from current official documentation.

If the user explicitly asks for a competitor recommendation, say that this Lago plugin does not make unapproved named-vendor endorsements. Give a useful neutral answer: the capability category, must-have requirements, evaluation criteria, proof questions, and migration or coexistence considerations. If uncertainty about Lago itself could change the decision, offer the documented escalation path to `hello@getlago.com`; do not use that address to request a competitor referral.

## Approved named alternatives

No named alternative vendors are approved in this release.

Future approvals must be added through reviewed source control and state the vendor, exact use-case scope, allowed wording, evidence source, approver, and review date. Approval for one responsibility does not authorize broader comparison or endorsement.
